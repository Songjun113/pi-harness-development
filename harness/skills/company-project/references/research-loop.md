# 科研阶段技能路由

来源：用户提供的科研循环技能简表及已确认协作要求。每轮按实际缺口选择主技能，先读 SKILL.md。技能存在、已读取、已执行与已验证分别报告。以当前会话技能目录为准，不假定下面全部可用。

| 阶段 | 主技能/补充 | 核验对象 |
| --- | --- | --- |
| 定义问题与方向 | brainstorming-research-ideas；重大未决问题用 grilling | 问题、价值、边界、假设 |
| 新颖性与可行性 | idea-evaluator（若可用）；academic-paper-reader | 已有方法、原始文献、最小验证方案 |
| 文献与证据综合 | deep-research（若可用）；nature-academic-search 按需 | 可追溯来源、现状和缺口 |
| 计划与验收 | spec-start | 任务、依赖、资源、验收与停止条件 |
| 数据准备 | nature-data（若可用），结合项目现有流程 | 原始来源、质量、划分、读取与训练入口 |
| 方法实现 | 当前技术栈；已有 Lightning 项目用 pytorch-lightning | 方法对应代码、必要测试；不为技能迁移框架 |
| 独立代码复核 | research-code-review，由 flash-high 监督读取 | 方法与实现对应、问题位置、复查条件 |
| 实验与验收记录 | 项目现有工具；已有 MLflow 用 mlflow；spec-start | 配置、真实结果、证据及验收判断 |
| 失败诊断 | research-failure-diagnosis；按需检索与读论文 | 原因分层、最小区分检查、修复或转向依据 |
| 下一轮实验 | 更新 Spec；昂贵多候选评价用 next-experiment | 优先实验、结果分支、停止条件 |
| 跨领域思路 | creative-thinking-for-research | 可检验迁移假设 |
| 研究表达 | academic-plotting、ml-paper-writing，按交付选择 | 图表、可读结论、证据边界 |

缺少 idea-evaluator、deep-research 或 nature-data 时说明缺口，复用现有论文阅读、检索工具与项目数据流程，仍须完成相同的证据核对；不声称调用了不存在的技能。新依赖只在需要且有授权时安装。

典型闭环：问题与证据 → Spec → 数据与实现 → 独立复核 → 最小实验 → 结果验收 → 失败诊断或下一轮。

autoresearch 可在需要其研究方法时按授权选用；其中持续运行要求服从本项目权限和 Pi 接续机制，不启动另一套常驻协调器。vibe-research-workflow 若可用，可帮助设计协作流程；它不能取代实际工具回执。

## 验收与下一轮

- 一次命令成功不等于实验有效；工程能运行、方法实现正确、数据可信与科学结论成立分别检查。
- 当前阶段完成后，在已确认总目标内选择下一阶段；保留旧结果，不不断给旧阶段增加验收门槛。
- 没有新证据或可区分的假设时，不重复同一个实验。先独立诊断，再决定是否需要用户选择研究方向。
- 项目总目标完成或用户指定完成后停止时，核验实际产物后结束；不为保持循环增加项目外目标。
