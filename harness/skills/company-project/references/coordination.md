# 协作与交接

## 保留一个当前状态入口

沿用 Spec 中的 tasks/status/实验记录，记录当前任务、负责人、证据位置、真实结果及下一步。运行句柄、监督 conversation_id 只保存在本项目已有受保护的运行记录中，不写入共享技能或跨项目全局配置。没有必要持久化的普通任务无需新增账本。

用户反馈先核对是在改变目标、修正实现还是补充信息，更新对应 Spec。对已确认步骤直接执行；未决架构选择使用 grilling 给出建议、真实提问并等待回答。

## 子任务契约

按复杂度提供：

- 所解决的问题及与 Spec 要求的关系。
- 允许读取/修改的文件、输入数据和资源边界。
- 具体产物、验证方法、不能自行改变的决定。
- 何时返回、失败时需保留的证据。

核实工具支持的模型后才能指定 Luna。工具不支持模型覆盖时不要以提示词冒充模型选择。独立读取/检索可并行；共享文件写入串行或使用隔离工作树并审阅合并。

## 监督调用

先读取 agy-delegate。实际工具调用采用：

```text
agy_usage(model="flash-high", dir=<实际项目根目录>)
agy_execute(
  model="flash-high",
  mode="plan",
  dir=<实际项目根目录>,
  context="none",
  digest=true,
  prompt=<下面的审核任务>,
  timeout_ms=<与任务匹配的有限超时>
)
```

项目根目录必须真实可读；远程材料应使用已有授权访问方式或经核实版本的本地副本，并说明哪个是权威来源。不要向监督发送认证、无关会话、其他项目材料或完整私有习惯库。

审核任务写清：

> 你是本项目独立监督，只读审核。按列出的 Spec 要求，亲自读取指定版本的文件和证据：……。核对方法与实现、数据/评价有效性及本次结论的支持范围。报告实际读取范围、严重程度、文件位置/证据、最小修正或区分检查、复查条件和未验证项。不要仅按主管摘要作结论，不扩大既有权限，不执行大规模实验。

- 关键代码实现按 research-code-review；负结果按 research-failure-diagnosis。
- `model` 必须显式为 `flash-high`（当前为 Gemini 3.8 Flash High）；不传自定义 agent 参数，不使用会恢复成其他模型的会话。复用会话时检查原始模型和项目一致，无法确认则新建显式 flash-high 会话。Opus 仅在用户明确指定时使用，不作为静默回退。
- `mode=plan` 是工具只读模式，仍须明确任务范围；不把计划输出当作已经运行的测试。
- 需要真实执行验证时由主管按权限安排，向监督返回新证据后复查。
- 后台执行须保留工具返回的 handle，使用 agy_tasks 等待并 collect；超时/取消后核实回执，不盲目重复有副作用的任务。
- 配额查询显示 available 只证明配额查询结果，不能证明模型已在 CLI 注册或能成功推理。必须以实际执行回执判断监督可用性。
- 没有真实工具成功结果，不得声称监督已通过。不可用时记录失败信息、受影响节点和恢复条件，不回退其他模型。

## 分歧与阻塞

将分歧表达为可检验主张。例如“测试划分可能泄漏”应追踪数据来源和索引，不用多轮投票解决。监督指出具体风险时，主管先做最小检查或补充依据，再复查。

监督暂时不可用时，可完成已有授权且不依赖该审核的独立准备工作；不得越过审核节点运行依赖实验或宣称验收。没有其他合理任务时停止派单，按 Goal 参考请求暂停。

## 简短回执示例

```text
当前项目与 Spec：<实际路径>
主管：<实际 GPT provider/model>；监督：Gemini 3.8 Flash High（flash-high）
本轮：<要解决的问题>
已核验：<证据路径与检查结果>
等待/阻塞：<真实原因或无>
下一步与负责人：<具体任务>
持续接续：<已激活及真实回执 / 尚未激活 / 已暂停>
```

回执模板用于组织信息，不要求每轮复制全部字段。
